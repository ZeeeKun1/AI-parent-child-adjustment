# Windows实时摄像头与麦克风采集

## 当前边界

`live-test --dry-run`是正式实验实时链路的采集基础层。它验证真实设备发现、明确选择、音视频格式、统一时间线、有界队列、停止信号和设备释放，但不连接Qwen、不产生状态判断，也不执行干预。

该边界用于避免在设备采集尚未稳定时同时改变模型、四状态代码本、干预政策和输出逻辑。

## 数据流

```text
Windows DirectShow摄像头与麦克风
        ↓
PyAV统一采集图
        ↓
音频重采样：16 kHz / mono / PCM16 / 约100 ms
视频采样：JPEG / 最大1280×720 / 初始约1 fps
        ↓
严格递增的统一毫秒时间戳
        ↓
有界媒体队列
        ↓
格式、同步、丢帧、延迟和释放验证
```

本地视频与实时设备都实现`MediaSource`接口，并输出同一种`MediaChunk`。后续接入Qwen Provider时不需要重新定义媒体格式。

## 设备选择

```powershell
python -m coregulation_poc live-test --list-devices
```

命令返回摄像头和麦克风各自的稳定会话索引。采集命令必须明确提供索引或完整设备名称，不会静默使用系统默认设备。

```powershell
python -m coregulation_poc live-test `
  --camera-index 0 `
  --microphone-index 0 `
  --duration-seconds 10 `
  --session-id P01_live_device_check `
  --dry-run
```

设备不可用、权限被拒绝、音视频流缺失、设备中途断开或停止后线程无法退出时，命令以非零状态结束，并将可诊断原因写入运行结果。

## 队列与过载策略

- 音频队列默认最多100块。队列持续满载时，采集会显式失败，避免静默丢失连续音频。
- 图像队列默认最多10帧。过载时移除最旧图像，并在指标中累计`dropped_image_chunks`。
- 媒体块进入队列前必须使用同一时间线，并具有严格递增的时间戳。
- 结束时设置停止信号并主动关闭DirectShow容器，随后等待采集线程退出。

容量、100 ms音频块、1 fps图像间隔和最大分辨率都是可调整的工程参数，不是研究结论。

## 隐私与运行产物

实时干运行默认不保存原始音频、视频、JPEG或Base64负载。运行目录只包含：

- `manifest.json`：设备显示名称、硬件标识指纹、媒体格式、队列配置和隐私声明；
- `events.jsonl`：块类型、时间戳和字节数，不含负载；
- `metrics.json`：数量、丢帧、背压、延迟、时间范围和释放状态；
- `result.json`：是否通过、是否调用API以及错误原因。

硬件替代名称不会写入运行目录，只保存不可逆的短指纹。当前预留了`SpeakerSegment`数据结构，但在声纹方案经过选择和验证前，系统不会伪造家长或儿童身份绑定。
