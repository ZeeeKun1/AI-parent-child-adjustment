# 浏览器摄像头与麦克风采集服务

## 当前边界

`web-live`提供一个可由参与者浏览器打开的实时采集页面。浏览器在参与者明确勾选说明并接受系统权限提示后，采集摄像头和麦克风，并通过同源 WebSocket 将媒体发送到 Python 服务端。

默认模式完成“浏览器采集到服务器”的零 API 技术检查。显式加`--enable-closed-loop`后，服务端会把滚动媒体窗口接入 Qwen，并串联状态轨迹控制、策略选择和浏览器干预；浏览器回传文字显示与语音播放结果，下一轮只使用干预后的新媒体观察恢复情况。

## 数据流

```text
参与者浏览器 getUserMedia
        ↓
AudioWorklet：16 kHz / mono / PCM16 / 约 100 ms
Canvas：JPEG / 最大 1280×720 / 约 1 fps / frame_time_ms
        ↓
同源加密 WebSocket（正式部署使用 WSS）
        ↓
协议校验、严格递增时间戳、媒体大小检查
        ↓
现有 MediaChunk
        ↓
有界内存窗口 → Qwen 状态识别 → 时机控制 → 策略选择 → 双通道输出
        ↑                                                ↓
        └──────── 干预后新媒体观察 ← 浏览器执行回执 ────────┘
        ↓
不含原始媒体的元数据运行记录
```

音频块、图像帧和 DirectShow、本地视频回放采用同一个`MediaChunk`接口。四状态编码、介入时机、策略卡和输出逻辑不需要因浏览器采集而改变。

## 本地运行

安装依赖后启动：

```powershell
python -m coregulation_poc web-live --host 127.0.0.1 --port 8000
```

在同一台电脑打开：

```text
http://127.0.0.1:8000
```

`localhost`属于浏览器允许使用媒体设备的安全上下文例外。本地技术测试可以不填写实验访问码。

## 可选实时闭环与额度控制

先完成默认零 API 采集测试，再显式启用闭环：

```powershell
python -m coregulation_poc web-live `
  --host 127.0.0.1 `
  --port 8000 `
  --enable-closed-loop `
  --window-seconds 12 `
  --assessment-interval-seconds 12 `
  --max-assessments 3
```

默认不启用语音，因此模块四使用可审计的文字降级路径。只有再加`--enable-voice`才会为每条实际干预调用 Qwen TTS 并在浏览器自动播放 Maia 音频。状态识别和语音都只由服务器持有密钥；音频只在内存中转换为 WAV 并发送给当前浏览器，不写入采集目录。

`window`与`interval`控制技术调度，`max-assessments`限制单会话模型调用上限。这些值不参与四状态语义判断，也不应作为论文中的形成性研究阈值。

## 服务器部署要求

正式服务器必须先在`.env`中配置一个不少于 12 个字符的随机实验访问码：

```text
BROWSER_CAPTURE_ACCESS_TOKEN=<long-random-invitation-code>
```

然后监听服务器网卡：

```powershell
python -m coregulation_poc web-live --host 0.0.0.0 --port 8000
```

非本机监听而没有访问码时，程序会拒绝启动。访问码只用于建立会话，不写入运行记录。当前共享访问码是技术验证级保护；正式招募前应替换为逐参与者、可撤销且有有效期的会话邀请机制。

公网部署还必须满足：

- 使用 Nginx、Caddy 或云负载均衡器终止 HTTPS，并代理 WebSocket；参与者通过`https://`页面和`wss://`连接访问。
- 不直接把 Uvicorn 端口暴露到公网。
- 保持页面和 WebSocket 同源；服务端会拒绝 Host 与 Origin 不一致的浏览器连接。
- 将 API 密钥、实验访问码和证书保留在服务器环境变量或密钥管理服务中，不写入网页、日志或 Git。
- 在正式实验前确定云端处理、数据保留、删除计划和事件响应流程。

## 媒体与过载策略

- 浏览器使用 AudioWorklet 将实际声卡采样率连续重采样为 16 kHz 单声道 PCM16，每块 3200 字节。
- 浏览器约每秒生成一张最大 1280×720 的 JPEG，并在画面底部写入`frame_time_ms`。
- WebSocket 音频积压超过 4 MiB 时明确停止采集，避免静默丢失连续语音。
- 图像积压时允许跳过图像帧，并把数量写入客户端指标。
- 服务端拒绝错误音频长度、无法解码的 JPEG、超大媒体包和超过最大会话长度的时间戳。
- 客户端时间戳进入服务端后归一化为严格递增的统一毫秒时间线。

以上容量、间隔和阈值均是可验证的工程初值，不是形成性研究结论。

## 隐私与运行产物

每次成功建立浏览器会话后，仅在`data/output/runs/<run_id>/`写入：

- `manifest.json`：协议版本、媒体格式、有限浏览器能力和隐私声明；
- `events.jsonl`：媒体类型、时间戳和字节数，以及不含参与者证据原文和音频Base64的闭环状态、决策、策略与输出回执；
- `metrics.json`：音视频数量、字节数、时间范围、归一化次数、客户端丢帧，以及闭环评估、干预回执和 API 调用数量；
- `result.json`：正常结束、失败或中途断线状态，并明确记录是否发生 API 调用。

不会保存 PCM、JPEG、WebM、Base64、设备 ID、设备名称、远程 IP、实验访问码或 API 密钥。浏览器页面上的勾选仅是技术界面，不替代经伦理审批的正式知情同意流程。

## 已验证与待验证

自动测试已覆盖页面与健康检查、访问码、正常 WebSocket 会话、双模态格式、统一`MediaChunk`、元数据产物、错误音频和中途断线。

正式实验前仍必须在实际参与者浏览器和硬件上验证：

1. Chrome/Edge 的摄像头、麦克风权限与 AudioWorklet 行为；
2. 真实远场双人语音、摄像头角度、遮挡和网络抖动；
3. HTTPS/WSS 反向代理和逐参与者访问控制；
4. Qwen 滚动评估的真实端到端延迟、额度与断线恢复；
5. 自然话轮边界技术检测在真实双人语音中的准确性；
6. 文字/语音干预的可见性、可接受性及干预后观察窗口。
