# 视频片段准备规范

本规范只服务于技术可行性测试，不替代正式研究的招募、知情同意和数据管理方案。

## 片段内容

- 每个片段保留一个完整互动 episode：关键表现前 5–10 秒、核心互动、后续反应 5–10 秒。
- 技术测试优先使用 20–60 秒的连续片段；不要在 episode 中间拼接或加速。
- 四种状态各准备 2–3 个片段，既包含典型案例，也包含边界案例。状态标签由研究者依据编码表预先判断，不由模型生成。
- `high_risk` 必须包含足以观察持续模式的上下文；单个冲突瞬间不能作为高风险真值。

## 画面与声音

- 必须保留原始同期声，并尽量让家长和孩子都能听清。
- 固定机位应尽量同时覆盖家长、孩子和作业区域；不要求面部特写。
- 推荐 MP4、H.264 视频、AAC 音频、720p 或 1080p、25 或 30 fps。
- 不加字幕、音乐、滤镜、转场或时间水印；程序会按约 1 帧/秒抽取 JPEG，并将音频转换为 16 kHz 单声道 PCM。

## 匿名与记录

- 文件名只用化名编号，例如 `P01_normal_01.mp4`，不要包含姓名、学校或住址。
- 放入本项目的 `data/input/`；该目录已被 Git 忽略。
- 另行保存研究者真值表，至少记录：`clip_id`、预编码状态、关键证据起止时间、判断依据、编码者和是否达成一致。
- 只有在知情同意覆盖云端模型处理时才调用 API；测试前检查背景中的证件、校服校徽、地址和屏幕信息。
