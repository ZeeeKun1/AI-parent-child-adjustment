# 亲子共调节系统四状态人工测试剧本

## 1. 测试目的

本剧本用于人工验证最新版实时系统是否能够完成以下闭环：

1. 区分家长与儿童说话人；
2. 在连续互动中识别 `normal`、`fluctuation`、`dysregulation` 和 `high_risk`；
3. 对普通 `normal` 和全部 `fluctuation` 保持不干预，仅在明确积极事件后给予低频肯定；
4. 对 `dysregulation` 和 `high_risk` 选择匹配的支持策略并生成情境化话术；
5. 记录干预后恢复、部分恢复、未恢复或恶化；
6. 在活动结束后生成完整实验记录和单次总结。

本测试依据当前代码中的10秒观察窗口、跨窗口状态边界和120秒同事件干预间隔编写。它用于验证系统行为，不用于证明识别准确率。正式准确率仍需以独立标注数据进行评估。

## 2. 测试人员和安全要求

- 使用两名成年人分别扮演家长和儿童，不建议让真实儿童参与负向互动测试。
- 不要由同一个人分饰两个角色，否则腾讯声纹可能无法可靠区分双方。
- 所有冲突动作均为表演，不推搡、不击打、不摔物，不使用侮辱性或威胁性语言。
- 双方不要同时说话。每句话说完后停顿约1秒，保证转写和声纹比对能够获得清晰证据。
- 摄像头应同时拍到两人的上半身、面部、桌面、作业和笔。
- 测试过程中不要切换网页、锁屏或让浏览器进入后台。

## 3. 测试准备

### 3.1 设备摆放

1. 将摄像头放在桌面正前方，确保家长和儿童均完整入镜。
2. 将麦克风放在两人中间，双方与麦克风距离尽量接近。
3. 关闭电视、音乐和其他持续噪声。
4. 准备纸、笔和以下测试题：

   - 题目一：小明有12支笔，送给同学4支，还剩多少支？
   - 题目二：48除以6等于多少？
   - 题目三：小红有24颗糖，平均分给4个人，每人多少颗？
   - 高风险测试：准备4道简单加减法题，供家长连续代答。

### 3.2 页面信息

建议填写：

| 字段 | 测试值 |
|---|---|
| 任务名称 | 数学作业人工测试 |
| 作业学科 | 数学 |
| 任务难度 | 一般 |
| 儿童年级 | 三年级 |

选择任意家长和儿童头像。头像只影响页面称呼和显示，不改变状态规则。

### 3.3 声音录制

家长清晰朗读：

> 我是今天陪孩子做作业的家长，我们准备开始了。

儿童扮演者清晰朗读：

> 我是今天要做作业的孩子，我们准备开始了。

两人均使用随后表演时的正常音色，不要故意改变声线。确认两项录音均显示完成，再执行设备检查。只有摄像头和麦克风均显示正常时才开始活动。

### 3.4 研究端

研究人员在另一个浏览器窗口打开：

```text
https://测试网址/research
```

输入研究端访问码，重点观察：

- 说话人区分结果；
- 状态、置信度和状态变化时间；
- `task_process`、`support_need` 和 `support_target`；
- `action` 和 `reason_code`；
- 干预文字与语音是否实际呈现；
- 是否出现 `loop_error`。

## 4. 重要判读原则

系统不是通过某个关键词直接触发状态，而是判断整个互动序列。

| 系统状态 | 当前操作边界 | 预期动作 |
|---|---|---|
| `normal` | 双方协调回应，任务持续推进 | 通常为 `no_intervention`；明确积极事件后可为 `reinforce` |
| `fluctuation` | 约10–30秒的暂时失配，但仍有可观察的恢复能力 | `no_intervention` |
| `dysregulation` | 最近60秒内至少3个受扰窗口、其中至少2个连续、累计约30秒，并有催促、退出、冲突或双方越界等独立佐证；明显的多模态冲突也可能更早进入 | `intervene` |
| `high_risk` | 多个历史窗口持续出现控制—依赖、过度帮助、任务接管或强烈退出，短时提示未改变模式 | `progressive_support` |

当前版本只会在明确的积极事件（如任务完成、双方积极回应）之后，于自然停顿处给出简短肯定；普通的顺利进行不会反复提示，同类积极提示之间至少间隔 120 秒。波动状态仍不干预。

模型和网络存在延迟。每个场景必须维持到研究端出现目标状态，不能说完一句话后立即进入下一场景。状态识别是概率性的，实际出现时间允许有1–2个窗口的偏差。

## 5. 测试一：正常状态

### 5.1 目标

验证双方自然配合、儿童主动参与且任务持续推进时，系统识别为 `normal`；普通推进阶段不提示，任务完成后的自然停顿可出现一次简短肯定。

### 5.2 表演时长

保持40秒，不要提前结束。

### 5.3 逐段剧本

#### 0–10秒

家长看着儿童和题目，语速平稳：

> 你先把题目读一遍，不着急，读完再说。

儿童看题并朗读：

> 小明有十二支笔，送给同学四支，还剩多少支？

家长保持安静，不插话。

#### 10–20秒

儿童拿笔思考后说：

> 我觉得应该用十二减四。

家长等待儿童说完后问：

> 你可以说说为什么用减法吗？

#### 20–30秒

儿童边写边说：

> 因为送出去四支，所以从十二里面减掉四，等于八。

家长回应：

> 好，你再检查一下题目问的是什么。

#### 30–40秒

儿童检查后说：

> 问还剩多少支，答案是八支。检查完了。

家长说：

> 好，我们看下一题。

### 5.4 预期结果

| 字段 | 预期值 |
|---|---|
| state | `normal` |
| task_process | `smooth_progress`，末段也可能为 `completion` |
| support_need | 普通推进阶段为 `none`；末段可为 `positive_reinforcement` |
| support_target | 可依据积极行为指向 `both`、`parent` 或 `child` |
| action | 普通推进阶段为 `no_intervention`；明确完成事件后可为 `reinforce` |
| 页面提示 | 普通推进不提示；末段最多出现一次与当前表现相关的简短肯定 |

若出现 `fluctuation`，检查是否存在长时间停笔、家长打断、题目未推进或双方声音身份识别错误。

## 6. 测试二：波动及自主恢复

### 6.1 目标

验证短暂的讲解速度失配会进入 `fluctuation`，但在双方能够自行调整时不触发干预，并在连续约20秒稳定推进后恢复为 `normal`。

### 6.2 波动阶段：保持20–30秒

换到题目二。家长说话明显比正常阶段快，但不责备、不命令、不抢笔。

#### 0–10秒

家长连续解释：

> 这题先看四十八里面有几个六，也可以想六乘几等于四十八，然后再把商写出来，写完还要检查。

儿童一直看着题目，拿着笔，但没有开始写：

> 等一下，你说得有点快，我还没跟上。

#### 10–20秒

家长继续用较快语速解释：

> 就是先想乘法，再换成除法，看六乘几是四十八，然后那个数就是答案。

儿童保持面向题目并明确提出需要：

> 我还在想。你能不能只说第一步？

#### 20–30秒（如研究端尚未出现波动）

家长说：

> 你先按刚才那个方法想一下。

儿童不离开任务，继续看题并说：

> 好，我先想六乘几等于四十八。

### 6.3 预期波动结果

| 字段 | 预期值 |
|---|---|
| state | `fluctuation` |
| task_process | `pace_mismatch` 或 `brief_stall` |
| support_need | `task_pacing` |
| support_target | 通常为 `parent` |
| action | `no_intervention` |
| 页面提示 | 不出现干预 |

如果30秒内已经进入 `dysregulation`，说明表演中可能加入了过多催促、儿童退出或持续停滞。重新测试时减少命令和责备，并让儿童持续注视题目、主动提出具体需要。

### 6.4 自主恢复阶段：保持至少25秒

家长主动放慢语速：

> 好，我们只看第一步。你先想六乘几等于四十八，我先等你。

家长停止说话，等待约5秒。

儿童开始书写：

> 六乘八等于四十八，所以四十八除以六等于八。

家长等儿童写完后说：

> 你自己检查一下。

儿童检查并说：

> 检查完了，可以继续下一题。

### 6.5 预期恢复结果

- 第一个稳定窗口可能仍显示恢复中的 `fluctuation`，这是正常的暂定恢复。
- 连续约20秒有效推进且双方保持稳定后，应回到 `normal`。
- 全过程不应出现干预。

## 7. 测试三：失调及干预

### 7.1 目标

验证任务持续停滞、家长高频催促与儿童退出共同出现时，系统会从波动升级为 `dysregulation`，并根据支持对象生成干预。

### 7.2 表演时长

保持45–60秒，或持续到干预实际出现。不要在研究端刚显示一次波动时停止表演。

### 7.3 逐段剧本

换到题目三。家长逐渐加快语速，儿童逐渐退出任务。

#### 0–10秒

家长连续询问：

> 这道题怎么还没写？快一点，第一步是什么？

儿童拿着笔但暂时不写：

> 我还在想。

#### 10–20秒

家长用手指连续点题目：

> 先写这个。你怎么又停了？我刚才不是讲过了吗？

儿童说：

> 等一下，我不会。

儿童停止书写，但仍坐在原位。

#### 20–30秒

家长继续催促：

> 再算一遍。快写，答案到底是多少？

儿童沉默约5秒，随后把视线转向一旁，不回答。

#### 30–40秒

家长继续指着题目：

> 先做这个，不要停。你听见了吗？

儿童将书本轻轻向前推开，说：

> 我不想做了。

#### 40–60秒

家长每隔几秒重复一次：

> 回来先写这一行。

> 先把这题做完，快一点。

儿童双手离开纸笔、转头或抱臂，保持不回应；不要离开摄像头画面。

### 7.4 预期状态变化

1. 最初1–2个受扰窗口可能显示 `fluctuation`。
2. 当系统累计约30秒停滞、至少3个受扰窗口，并观察到高频催促和儿童退出后，应进入 `dysregulation`。
3. `task_process`通常应为 `pace_mismatch`、`sustained_stall` 或 `disengaged`。
4. `support_need`通常应为 `task_pacing`、`emotional_support`、`need_expression` 或 `mutual_understanding`。
5. `action`应为 `intervene`，页面应显示文字提示；启用语音时还应播放同义语音。

### 7.5 合理的干预范围

根据模型识别出的主要问题，以下任一方向均可判为合理：

- 面向家长的语气和节奏调整；
- 面向儿童的压力安抚或需求表达；
- 面向双方的相互理解重置；
- 建议家长先定位具体卡点，而不是继续增加讲解。

如果干预内容直接给出题目答案、责备某一方、与当前问题无关，或者只显示固定模板而没有结合当前情境，则判为失败。

## 8. 测试四：干预后结果

失调干预出现后，选择以下一个分支。两个分支需要分别运行两次失调场景，不能在同一次干预后同时测试。

### 8.1 分支A：恢复

家长立即降低语速并放下指题的手：

> 好，我先不催了。你告诉我具体卡在哪一步，我听完再说。

儿童重新看题：

> 我不知道为什么要用除法。

家长等待儿童说完：

> 明白了。我们先只看“平均分”是什么意思，你先说说自己的想法。

儿童重新拿笔并尝试书写。双方保持这种互动至少30秒。

预期结果：

- 干预后的第一个有效窗口可能为 `fluctuation`，结果记录为 `partial_recovery`；
- 连续约20秒恢复有效推进后进入 `normal`，结果记录为 `recovered`；
- 记录中可能出现“家长调整”“儿童重新参与”“任务继续推进”等解释标签。

### 8.2 分支B：未恢复

家长听到干预后仍继续：

> 先不说这些，赶紧把答案写出来。

儿童继续转头、停笔并说：

> 我还是不想做。

双方保持原模式至少30秒。

预期结果：

- 状态继续为 `dysregulation`；
- 干预结果为 `not_recovered`；
- 系统继续识别状态，但相同事件在120秒观察期内通常不会立即重复提示；
- 研究端出现 `same_episode_observation_period` 属于当前设计，不属于漏干预。

若要验证同一事件再次干预，应从第一次干预实际呈现后继续保持失调超过120秒。超过间隔后，系统可以再次选择策略并生成不同措辞。

## 9. 测试五：高风险状态

### 9.1 目标

验证持续的家长任务接管和儿童被动依赖能够在多个历史窗口中形成 `high_risk`。高风险不是“冲突更激烈”的同义词，其关键是模式长期、反复且短期支持没有改变。

### 9.2 测试方式

建议重新开始一个独立会话，持续2–3分钟。家长始终控制作业和书写，儿童始终等待指令。即使页面出现一次干预，也先按剧本继续表演，以验证模式未改善时系统能否保持高风险判断。

### 9.3 逐段剧本

#### 0–30秒：建立任务接管

家长拿着儿童的笔，指着第一道题：

> 这一步写六，下一步写三，你照着我说的写。

儿童不主动计算：

> 那下一步写什么？

家长直接在纸上写一步：

> 这里我来写，你照着看就行。

儿童将笔交给家长，双手离开作业。

#### 30–60秒：强化被动依赖

家长继续逐步给出答案：

> 不用自己试，我告诉你。这里先加，再把这个数写下来。

儿童问：

> 你告诉我答案就行。

家长拿走作业或橡皮，替儿童改写：

> 这里写错了，我直接帮你改。

儿童保持等待，不解释思路、不主动拿回笔。

#### 60–90秒：重复同一模式

家长翻到下一题：

> 下一题也按我说的做。第一步写四，第二步写二。

儿童说：

> 好，下一步呢？

家长继续代写或逐字指令，儿童仅机械照做。

#### 90–150秒：验证模式持续

如系统已经提示“把下一步交还给孩子”，家长仍然说：

> 他自己做太慢了，我直接告诉他更快。

儿童继续说：

> 你帮我写吧，我等你告诉我。

重复相同的接管—等待模式，不加入新的冲突或辱骂。

如需测试超过120秒后的再次支持，继续保持到第一次干预实际呈现后的第121秒以上。

### 9.4 预期结果

| 字段 | 预期值 |
|---|---|
| state | 历史不足时可能先为 `fluctuation` 或 `dysregulation`；多个窗口后进入 `high_risk` |
| interaction_performance | `parental over-helping or task takeover`、`child passive dependence` 或 `persistent interaction imbalance` |
| task_process | `over_assistance` |
| support_need | `autonomy_support` |
| support_target | 通常为 `parent`，也可能为 `child` 或 `both` |
| action | 首次可执行高风险判断应为 `progressive_support` |

合理策略包括：

- 请家长把下一步交还给儿童；
- 请家长减少代答和即时纠正；
- 让儿童自己决定先尝试哪一步；
- 强调AI和家长都不应代替儿童完成任务。

一次代答、一次纠错或一次拿笔不应直接形成 `high_risk`。如果第一个10秒窗口就被判为高风险并立即干预，应检查状态历史和模型证据是否合理。

## 10. 可选安全边界测试：证据不足

该测试不属于四状态，但用于验证系统不会在看不清、听不清时随意干预。

1. 重新开始一个短会话。
2. 双方保持沉默15秒，作业移出画面，但不要遮挡或损坏设备。
3. 或者保持人在画面中，但不进行任何可判断的作业互动。

预期结果：

- `state`为 `null`，或者状态置信度为低；
- `action`为 `hold`；
- `reason_code`为 `insufficient_evidence` 或 `low_confidence`；
- 不出现干预。

## 11. 测试通过标准

### 11.1 说话人和设备

- [ ] 家长、儿童录音均注册成功；
- [ ] 摄像头和麦克风均显示正常；
- [ ] 研究端能够看到家长和儿童语音片段；
- [ ] 不是所有片段都被长期识别成同一个角色；
- [ ] 低置信片段有明确记录，不被伪装成高置信结果。

### 11.2 四状态

- [ ] 正常互动出现 `normal`，普通推进不干预，明确积极事件后至多出现一次肯定；
- [ ] 10–30秒暂时失配出现 `fluctuation`，且不干预；
- [ ] 连续有效恢复约20秒后回到 `normal`；
- [ ] 持续停滞加独立佐证后出现 `dysregulation`；
- [ ] 失调状态出现至少一次匹配当前问题的干预；
- [ ] 持续控制—依赖模式最终出现 `high_risk`；
- [ ] 高风险支持方向与自主性或任务接管有关。

### 11.3 干预和记录

- [ ] 干预文字与当前对话相关，而不是无关固定话术；
- [ ] 启用语音时能够正常播放，文字与语音核心含义一致；
- [ ] 模型响应期间摄像头和麦克风继续采集；

## 13. 结果解释

- 状态首次出现时间允许有1–2个窗口偏差，但状态变化的总体方向应符合剧本。
- 单次没有识别到目标状态不能直接证明规则错误，应先检查声纹、转写、摄像头范围、证据持续时间和API错误。
- 如果同一剧本重复多次仍系统性偏向某一状态，才应进入状态边界校准。
- 如果状态正确但没有干预，检查置信度、证据充分性、`support_need`、`support_target`、模型延迟以及120秒同事件观察间隔。
- 如果状态和策略均正确但话术不自然，应单独调整策略排序或话术生成，不应反向修改状态边界。
